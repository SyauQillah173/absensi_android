

Aturan:

- Jangan membuat wilayah dari text typo.
- Simpan ID wilayah.
- Nama wilayah hanya untuk tampilan.

## 4. Prinsip Wajib untuk Pekerjaan Lanjutan

Wajib:

- analisa file sebelum mengubah;
- jaga UI Android tetap konsisten;
- role login hanya `admin`, `guru`, dan `wali`;
- santri/siswa hanya data anak, bukan akun login;
- pakai pola kode yang sudah ada;
- relasi database harus berbasis ID;
- import Excel harus mapping ke master ID;
- export PDF/Excel tetap menampilkan nama rapi;
- offline cache harus membawa ID relasi;
- role access harus berbasis ID;
- update dokumentasi jika ada perubahan besar.
- realtime yang dimaksud saat ini adalah auto-refresh in-app lewat `SyncService`, heartbeat, pull refresh, dan reload screen aktif; belum push server/FCM saat aplikasi tertutup.

Dilarang:

- mengubah desain UI tanpa diminta;
- membuat relasi memakai nama/text bebas;
- membuat master table dobel;
- menghapus data tanpa backup;
- menjalankan `migrate:fresh` pada data production;

- menghapus kolom legacy tanpa validasi penuh.

- Pindah kamar/komplek santri pondok harus lewat edit.
- Aktifkan ulang santri pondok wajib membuat `participates_prayer = true`.
- Absensi Jama'ah Sholat memakai relasi pondok, bukan text bebas.
- Absensi Sholat punya bulk save, rekap, dashboard summary, cancel soft, wali endpoint, dan akses guru berbasis kamar/komplek.
- Dashboard harus refresh saat topic `absensi_sholat` berubah.
- Pembayaran memakai `payment_bills` sebagai sumber status tagihan.
- Pembayaran umum harus menampilkan `Kurang Bayar` jika nominal dibayar kurang dari tagihan.
- Pembayaran bulanan bisa mengikuti mode `semester` atau `full_year` dari CMS periode pembayaran.
- CMS Keuangan punya master `payment_methods` dan `payment_period_types`.
- Tipe Pembayaran tetap master tagihan, dengan nominal default dan periode pembayaran.
- Role admin diperluas dengan tipe admin: utama, bendahara, pondok, absensi, akademik/lainnya.
- Admin utama full access; admin lain mengikuti permission.
- Wali tetap read-only dan hanya melihat anak yang terhubung.

Jika melanjutkan pekerjaan:

- Jangan hapus schema dump PostgreSQL.
- Jangan reset database tanpa backup.
- Jangan menganggap file untracked controller/model/service/migration baru sebagai sampah.
- Jangan mencampur Absensi Madin dan Absensi Sholat pada tabel/query yang sama.
- Jangan menyimpan relasi komplek/kamar sebagai text bebas.
- Jangan membuat status `Lunas` hanya dari transaksi berhasil; hitung dari tagihan dan dibayar.
- Setelah mengubah modal/bottom sheet, cek lifecycle `mounted/context.mounted`.
- Setelah mengubah Flutter, jalankan `dart analyze`.
- Setelah mengubah backend, jalankan `php -l` dan `php artisan route:list`.
