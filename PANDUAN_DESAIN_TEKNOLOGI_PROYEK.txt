# PANDUAN DESAIN DAN TEKNOLOGI PROYEK

Update: 29 Mei 2026
Project: Absensi Android + Laravel Backend

Dokumen ini menjelaskan identitas tampilan, warna, font, icon, bahasa, teknologi, dan aturan konsistensi proyek. Tujuannya supaya setiap pengembangan berikutnya tidak merusak tampilan awal aplikasi dan tetap mengikuti sistem yang sudah ada.

## 1. Aturan Utama

Aturan paling penting:

- Jangan mengubah konsep tampilan Android tanpa permintaan khusus.
- Jangan mengganti warna utama sembarangan.
- Jangan mengganti font utama.
- Jangan mengganti jenis icon utama.
- Jangan membuat halaman dengan gaya desain baru yang berbeda dari halaman lama.
- Perubahan sistem, database, API, dan logic boleh dilakukan, tetapi UI harus tetap konsisten.
- Jika membuat fitur baru, tampilannya harus terasa seperti bagian asli aplikasi.
- Refactor terbaru tidak mengubah desain UI/UX utama, hanya memperkuat payload, validasi, actor, dan keamanan backend.
- Perbaikan terbaru hanya menambah pesan/status kecil yang membantu user memahami error, tanpa mengubah palet, layout, font, icon, dashboard, atau navigasi utama.
- Animasi sukses dan refresh terbaru bersifat reusable dan kecil, tetap mengikuti palet teal/kuning yang sudah ada.
- Realtime terbaru adalah realtime in-app saat aplikasi aktif, bukan perubahan desain dashboard atau push notification eksternal.
- Refresh terbaru juga diterapkan di Beranda dashboard dengan wrapper yang sama, tanpa mengubah struktur dashboard atau bottom navigation.
- Fondasi responsif terbaru memakai `AppResponsive` untuk padding, max width, dan scroll konsisten pada layar prioritas, tanpa mengubah warna, font, ikon, role dashboard, atau navigasi.
- Responsive terbaru juga memperkuat dashboard, kartu absensi, menu grid, bottom navigation, flow absensi, mapel, nilai, dan buku induk agar aman di HP kecil, Poco M6, layar besar, dan font scale lebih tinggi.
- Semua teks panjang seperti kelas/mapel/jadwal wajib memakai `Flexible`, `Expanded`, `Wrap`, `maxLines`, `ellipsis`, atau layout adaptif agar tidak terjadi `RenderFlex overflow`.
- Tombol PDF rekap pembayaran wali disembunyikan saat belum ada transaksi agar UI tidak menampilkan aksi kosong.
- Menu baru tetap mengikuti konsep awal. Contoh terbaru: `Setting Akademik` ditempatkan di Buku Induk dengan background kuning, panel biru muda, card putih, aksen teal, rounded UI, dan font Poppins.
- Modal/picker baru seperti master sekolah harus berupa bottom sheet yang rapi dan aman lifecycle, bukan dialog bertumpuk yang rawan red screen.
- Field baru di Edit Data Santri harus ditambahkan sebagai bagian form yang sudah ada, bukan halaman/desain baru yang berbeda.
- Tab baru `Per Santri` pada Pembayaran tetap memakai struktur lama Keuangan, bukan menu terpisah dengan gaya baru.
- Tampilan tagihan Admin/Wali memakai card ringkasan, badge status, filter rounded, dan grid bulanan horizontal yang mobile-friendly.
- Grid pembayaran bulanan boleh horizontal scroll, tetapi tidak boleh memaksa tabel terlalu lebar tanpa scroll di HP kecil.
- Badge periode seperti `2025/2026 • Genap` wajib memakai chip kecil, bukan teks besar yang mengganggu layout.
- Error Flutter `_dependents.isEmpty` harus dicegah dengan lifecycle modal yang aman, terutama pada Edit Mata Pelajaran saat hapus/tambah guru pengajar.
- Update 17 Mei 2026: tombol `Sinkronisasi Data Santri` di Setting Akademik wajib mengikuti gaya tombol teal/rounded yang sama, dengan loading dan pesan sukses singkat.
- Update 17 Mei 2026: form pembayaran SPP/bulanan memakai chip/checklist bulan Jul-Jun yang mobile-friendly; bulan yang sudah lunas tampil disabled dan tidak boleh terlihat seperti tunggakan.
- Update 17 Mei 2026: dropdown siswa pembayaran boleh kosong jika tahun ajaran belum disinkronkan, tetapi pesan harus manusiawi dan mengarahkan admin ke Setting Akademik.
- Update 17 Mei 2026: jadwal mapel berbeda hari/jam harus tampil sebagai item terpisah dengan key jadwal unik, bukan tertimpa oleh item kelas/guru yang sama.

## 16. Sistem Offline dan Realtime

Sistem memakai:

```text
sqflite
shared_preferences
connectivity_plus
SyncService
CacheService
LocalDbService
```

Fungsi:

- menyimpan session login;
- menyimpan data lokal;
- mendukung akses saat offline;
- mengirim data pending saat online;
- refresh dashboard secara cerdas.
- menyimpan detail gagal sync absensi jika backend memberi pesan error.

Aturan:

- cache lokal harus membawa ID relasi;
- label text boleh disimpan untuk tampilan;
- pending sync tidak boleh hanya mengandalkan nama text;
- pending sync absensi harus membawa `class_id`, `mapel_id`, `jadwal_id`, dan `attendance_status_id` jika tersedia;
- absensi valid memakai `attendance_key` stabil berbasis `tanggal`, `class_id`, `mapel_id`, `jadwal_id`, dan `siswa_id`;
- create absensi harus bersifat create-only conflict-safe; jika scope yang sama sudah masuk server, request baru menjadi conflict dan tidak menimpa data lama;
- edit absensi final harus lewat `PUT /api/absensi/{id}`;
- sync offline absensi memakai aturan server-first sehingga pending offline tidak boleh overwrite data server yang sudah masuk lebih dulu;
- data completed dari server yang sudah tercache dikunci saat offline dan tidak boleh diabsen ulang, diedit, atau dibatalkan sampai online;
- pending offline hanya boleh diedit oleh actor yang membuat pending tersebut;
- dashboard tidak boleh menampilkan data absensi incomplete sebagai `Unknown`;
- saat sync selesai dengan error/conflict, UI perlu mendapat event refresh agar status pending/gagal cepat terlihat;
- jika data master berubah, cache harus ikut disesuaikan.
- `SyncService.notifyDataChanged` dipakai sebagai event bus lokal untuk topic siswa, pembayaran, mapel/jadwal, absensi, dan heartbeat.
- Layar wali pembayaran dan riwayat absensi listen event sync agar data reload saat aplikasi aktif.
- Realtime in-app tidak sama dengan push notification saat aplikasi tertutup; untuk itu perlu Firebase/FCM atau layanan push lain.
- Update 9 Mei 2026: topic sync mencakup `user` dan `profile` agar Data Diri Guru refresh setelah admin mengubah data guru.
- Perubahan guru pengajar/jadwal mapel harus mengirim refresh topic mapel dan absensi agar list/count aktif ikut diperbarui saat aplikasi aktif.

## 27. Kesimpulan

Identitas proyek ini adalah:

```text
Flutter Android dengan tampilan kuning lembut,
font Poppins,
Material rounded icons,
UI rounded dan mobile-first,
backend Laravel API,
database PostgreSQL normalized,
offline-friendly,
dan role admin/guru/orang tua.
```

Setiap perubahan ke depan harus menjaga identitas ini. Perubahan sistem boleh besar, tetapi tampilan wajib tetap konsisten dengan desain awal.
