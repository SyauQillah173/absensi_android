================================================================
   8. ALUR DATA PALING SEDERHANA
================================================================

Alur normal online:
  1. User buka screen Flutter
  2. Screen panggil ApiService
  3. ApiService request ke backend Laravel
  4. Route api.php arahkan ke controller
  5. Controller akses model
  6. Model akses PostgreSQL
  7. Response JSON balik ke Flutter
  8. UI tampil

Alur offline:
  1. API gagal
  2. CacheService ambil data lokal
  3. Jika user input data tertentu, data masuk local queue
  4. Saat online lagi, SyncService kirim ke backend

================================================================
   10A. PEMBELAJARAN KHUSUS UNTUK KAMU: PHASE 44
================================================================

Kalau tujuanmu bukan cuma "bisa pakai", tapi benar-benar "paham sistem",
pelajari 4 ide ini dari perubahan terbaru:

1. Satu masalah bisa punya dua akar:
  - akar di backend
  - akar di state frontend

Contoh nyata:
  bug guru pengajar "muncul lagi" ternyata bukan cuma bug UI.
  Akar backend:
    - relasi guru mapel ada di mapel_guru
    - tetapi jadwal masih menyimpan nama guru di field string jadwal.guru
  Akar frontend:
    - draft hapus guru lokal bisa tertimpa lagi oleh refresh detail mapel

Pelajaran:
  kalau lihat data "mental", jangan langsung salahkan widget.
  Cek source of truth dan alur refresh datanya.

2. Data sensitif butuh pagar sebelum simpan:
  pembayaran bukan sekadar form input.
  Admin boleh full access, tetapi transaksi tetap butuh verifikasi identitas.

Pelajaran:
  "punya hak akses" tidak sama dengan "boleh lewat tanpa verifikasi".

3. Multi pembayaran mengubah cara berpikir schema:
  sebelumnya:
    1 baris pembayaran = 1 item pembayaran
  sekarang:
    1 transaksi induk = banyak item pembayaran

Pelajaran:
  saat kebutuhan bisnis berubah, sering kali tabel lama masih dipakai,
  tetapi butuh lapisan baru agar laporan lama tidak rusak.

4. Fitur launch bukan cuma tambah fitur:
  menghapus teks akun percobaan juga bagian dari engineering produk.

Pelajaran:
  kesiapan rilis bukan hanya soal logic benar, tetapi juga soal tampilan
  publik yang bersih, aman, dan profesional.

5. Izin Guru
  - guru kirim izin
  - admin pantau

================================================================
   14. RINGKASAN SUPER SINGKAT UNTUK DIHAFAL
================================================================

Kalimat hafalan:
  Project ini adalah aplikasi Flutter + Laravel + PostgreSQL
  untuk madrasah diniyah.
  Sistem ini multi-role: admin, guru, wali.
  Fitur paling pentingnya adalah absensi offline-first.
  UI utamanya memakai font Poppins, Material Icons, dan warna
  kuning-hijau-biru muda.
  Alur datanya adalah:
  screen Flutter -> ApiService -> route Laravel -> controller ->
  model -> PostgreSQL.
  Saat offline, aplikasi memakai cache SQLite dan sync otomatis.
