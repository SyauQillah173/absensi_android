# PANDUAN DATABASE

Update: 2 Juni 2026
Project: Absensi Android + Laravel Backend
Database utama: PostgreSQL

Dokumen ini adalah panduan belajar dan maintenance database setelah rombak besar sistem data. Panduan lama diganti total karena struktur database sekarang memakai pendekatan master data, ID relasi, foreign key, constraint, dan index.

## 1. Tujuan Database Baru

Database dibuat supaya:

- data tidak bergantung pada text bebas sebagai relasi;
- typo tidak mudah masuk sebagai data baru;
- relasi guru, siswa, kelas, mapel, pembayaran, absensi, wilayah, dan role bisa dilacak dari ID;
- aplikasi Android dan web nantinya membaca sumber data yang sama;
- import Excel, export PDF/Excel, offline sync, dan role access tetap konsisten;
- maintenance lebih mudah karena master data jelas.

Prinsip utamanya:

- ID adalah sumber kebenaran relasi.
- Text hanya dipakai untuk tampilan, label, riwayat, export, atau kompatibilitas lama.
- Data master tidak boleh dibuat sembarangan dari input typo.
- Data penting harus punya foreign key, unique constraint, check constraint, atau index sesuai kebutuhan.

Contoh:

```text
Salah:
absensi.nama_guru = "Diki"
absensi.kelas = "Sifir Awal A"
absensi.mapel = "Akhlaq"

Benar:
absensi.teacher_id = 2
absensi.class_id = 10
absensi.mapel_id = 4
```

- Jangan menambah migration baru tanpa memahami schema baseline.
- Jangan menghapus kolom lama tanpa strategi migrasi dan validasi.

## 3. Cara Reset Database Bersih

Masuk ke folder backend:

```bash
cd absensi_backend
```

Jalankan migration dan seeder:

```bash
php artisan migrate:fresh --seed
```

Catatan Windows:

Jika muncul error seperti ini:

```text
'psql' is not recognized as an internal or external command
```

berarti PostgreSQL sudah dipakai Laravel untuk koneksi, tetapi command line `psql` belum masuk PATH Windows. Tambahkan folder `bin` PostgreSQL ke PATH, contoh sementara di PowerShell:

```powershell
$env:Path = "C:\Program Files\PostgreSQL\18\bin;$env:Path"
```

Setelah itu jalankan ulang:

```bash
php artisan migrate:fresh --seed
```

Setelah itu import wilayah resmi:

```bash
php -d memory_limit=512M artisan regions:import-sql
```

Jika ingin drop semua tabel manual dari PgAdmin sebelum reset:

```sql
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
GRANT ALL ON SCHEMA public TO postgres;
GRANT ALL ON SCHEMA public TO public;
```

Setelah drop manual, tetap jalankan dari Laravel:

```bash
php artisan migrate:fresh --seed
php -d memory_limit=512M artisan regions:import-sql
```

Kenapa import wilayah dipisah?

- data wilayah Indonesia sangat besar;
- jumlah desa/kelurahan bisa puluhan ribu;
- lebih aman dipisah dari seeder utama;
- kalau database di-reset, wilayah harus di-import ulang.

## 3A. Cara Backup dan Download Database Besar

Backup wajib dilakukan sebelum reset database, sebelum rilis, atau sebelum perubahan besar.

Format backup yang disarankan adalah custom dump PostgreSQL:

```bash
pg_dump -U postgres -h 127.0.0.1 -p 5432 -d absensi_db -F c -f backup_absensi_db.dump
```

File hasil backup:

```text
backup_absensi_db.dump
```

File ini bisa dipindahkan atau didownload seperti file biasa ke flashdisk, Google Drive, harddisk eksternal, atau folder backup lain.

Contoh backup dengan nama tanggal di PowerShell:

```powershell
$tanggal = Get-Date -Format "yyyyMMdd_HHmmss"
pg_dump -U postgres -h 127.0.0.1 -p 5432 -d absensi_db -F c -f "backup_absensi_db_$tanggal.dump"
```

Jika ingin backup bentuk SQL biasa:

```bash
pg_dump -U postgres -h 127.0.0.1 -p 5432 -d absensi_db -F p -f backup_absensi_db.sql
```

Catatan:

- gunakan `.dump` untuk backup besar karena lebih cocok direstore dengan `pg_restore`;
- gunakan `.sql` kalau ingin file bisa dibaca manual sebagai teks SQL;
- jangan menjalankan `migrate:fresh` sebelum backup jika database sudah berisi data penting;
- simpan minimal 2 salinan backup di tempat berbeda.

Restore dari file `.dump`:

```bash
pg_restore -U postgres -h 127.0.0.1 -p 5432 -d absensi_db --clean --if-exists backup_absensi_db.dump
```

Restore dari file `.sql`:

```bash
psql -U postgres -h 127.0.0.1 -p 5432 -d absensi_db -f backup_absensi_db.sql
```

Jika ingin restore ke database kosong baru:

```sql
CREATE DATABASE absensi_db_restore;
```

Lalu:

```bash
pg_restore -U postgres -h 127.0.0.1 -p 5432 -d absensi_db_restore backup_absensi_db.dump
```

Backup cepat sebelum reset total:

```bash
pg_dump -U postgres -h 127.0.0.1 -p 5432 -d absensi_db -F c -f backup_sebelum_reset.dump
php artisan migrate:fresh --seed
php -d memory_limit=512M artisan regions:import-sql
```

Catatan master absensi terbaru:

- `absensi.attendance_key` menjadi key stabil untuk satu siswa, satu kelas, satu mapel, satu jadwal, dan satu tanggal.
- Format logis `attendance_key` adalah `tanggal_classId_mapelId_jadwalId_siswaId`.
- Absensi berbasis jadwal wajib membawa `siswa_id`, `tanggal`, `class_id`, `mapel_id`, dan `jadwal_id`.
- Status UI `H/S/I/A` diterima backend lalu dinormalisasi ke `Hadir/Sakit/Izin/Alfa`.
- `POST /api/absensi` sekarang bersifat create-only conflict-safe: jika `attendance_key` sudah ada, backend mengembalikan `conflict:true` HTTP 409 dan tidak menimpa data server.
- Edit data final hanya lewat `PUT /api/absensi/{id}`.
- `POST /api/absensi/bulk` membuat data baru per item dan menandai item yang sudah ada sebagai conflict/failed, bukan overwrite.
- Sync offline dengan `diinput_via=offline_sync` tidak boleh menimpa data server, termasuk jika pending offline dibuat oleh admin.
- Admin full access untuk edit semua absensi final lewat `PUT`, sedangkan guru hanya boleh edit absensi dengan `actor_user_id` miliknya sendiri.
- Guru hanya boleh input absensi pada jadwal/mapel yang ditugaskan admin.
- Dashboard tidak boleh menampilkan data absensi yang `class_id`, `mapel_id`, atau `jadwal_id` kosong sebagai `Unknown`.

Catatan pembayaran:

```text

```

Catatan pembayaran terbaru:

- `payment_type_id` tetap menjadi sumber resmi jenis tagihan.
- `payment_bill_rules` menyimpan aturan tagihan otomatis, misalnya sekali bayar atau bulanan, nominal, target semua santri/kelas/santri tertentu, periode aktif, dan tanggal jatuh tempo.
- `payment_bills` menyimpan tagihan aktual per siswa dan periode. Unique key `payment_bill_rule_id + siswa_id + period_key` mencegah tagihan dobel untuk bulan yang sama.
- `payment_bill_notifications` menyimpan rencana/pencatatan notifikasi tagihan. Saat ini kanal utama adalah `in_app`; struktur metadata disiapkan untuk WhatsApp gateway dan email.
- `pembayaran.payment_bill_id` menghubungkan pembayaran yang dicatat admin ke tagihan tertentu. Jika transaksi lunas, tagihan terkait ikut berubah menjadi `Lunas`.
- Command `payments:generate-bills` membuat tagihan otomatis secara idempotent dan aman dijalankan berulang.
- Kolom legacy `pembayaran.jenis` masih punya check constraint lama sehingga hanya boleh berisi kategori legacy seperti `SPP Bulanan`, `Ujian Semester`, `Buku & Kitab`, `Daftar Ulang`, atau `Lainnya`.
- Jika admin membuat tipe pembayaran baru seperti `Kitab`, nama resminya tetap dibaca dari `payment_types`, sedangkan `pembayaran.jenis` disimpan sebagai kategori legacy aman agar database tidak menolak transaksi.
- Error PostgreSQL `pembayaran_jenis_check` pada `POST /api/pembayaran` diperbaiki dengan canonical mapping di backend, bukan dengan menyimpan label liar.

## 7. Text Legacy

Beberapa kolom text masih dipertahankan untuk:

- tampilan lama di Android;
- export PDF/Excel;
- cache offline;
- kompatibilitas endpoint lama;
- riwayat label pada transaksi.

Namun aturan barunya:

- text bukan sumber relasi utama;
- text harus mengikuti master ID jika tersedia;
- input typo tidak boleh otomatis membuat master baru;
- query penting harus diarahkan ke ID.

Contoh text yang boleh tetap ada sebagai label:

```text
nama_siswa
nama_kelas
nama_mapel
nama_wilayah
status_label
```

Contoh ID yang harus jadi sumber relasi:

```text
student_id
class_id
subject_id/mapel_id
teacher_id
guardian_id
province_id
city_id
district_id
village_id
status_id
```

## 8. Anti Typo dan Data Guard

Sistem sudah diarahkan supaya tidak membuat data master sembarangan.

Contoh yang harus ditolak:

```text
Gresikk
Sifir AwaI
Diky
Mapel typo
Status pembayaran bebas
```

Kalau input berasal dari Excel:

- nama boleh ditulis di Excel agar mudah diisi;
- backend harus mapping ke master ID;
- field wajib atau format penting yang tidak valid tetap menjadi error validasi;
- field master opsional yang tidak cocok dikosongkan dan masuk `warnings`, bukan menggagalkan seluruh baris;
- jangan otomatis membuat master baru tanpa konfirmasi admin.
- import siswa memakai kolom `kelompok_belajar` untuk masuk otomatis ke kelompok belajar jika nama kelompok cocok master;
- header lama `kelas_sifir` masih diterima untuk kompatibilitas file lama.
- `asal_sekolah` pada import harus cocok dengan master `school_origins` jika diisi;
- `jenis_santri` resmi hanya `Santri Pondok`, `Santri Madin`, atau `Keduanya`;
- jangan menyimpan label liar dari typo ke database untuk master opsional.

Format import terbaru:

```text
Data Siswa wajib:
nis, nama_lengkap_siswa, jenis_kelamin

Data Siswa disarankan:
nama_wali, status_siswa, kelompok_belajar

Data Guru wajib:
name, kode_guru, phone, email, status, password

Data Admin/User wajib:
name, email, phone, role, password, status
```

Response import siswa tetap kompatibel, tetapi sekarang dapat menambahkan:

```text
warnings
```

`warnings` dipakai untuk memberi tahu baris dan field opsional yang dilewati, misalnya `jenis_santri`, `asal_sekolah`, wilayah, pendidikan, pekerjaan, penghasilan, tempat tinggal, transportasi, atau golongan darah yang tidak cocok dengan master.
