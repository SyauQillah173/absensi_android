## 5. Reset dan Isi Database

Karena database sudah dirombak besar, cara paling bersih adalah:

```bash
php artisan migrate:fresh --seed
```

Catatan Windows jika `psql` tidak dikenali:

```text
'psql' is not recognized as an internal or external command
```

Laravel PostgreSQL memakai command `psql` untuk load schema dump. Pastikan folder `bin` PostgreSQL masuk PATH Windows. Contoh sementara di PowerShell:

```powershell
$env:Path = "C:\Program Files\PostgreSQL\18\bin;$env:Path"
```

Jika versi PostgreSQL berbeda, sesuaikan angka foldernya. Setelah PATH benar, jalankan ulang:

```bash
php artisan migrate:fresh --seed
```

Lalu import wilayah resmi:

```bash
php -d memory_limit=512M artisan regions:import-sql
```

Jika database sudah ada dan tidak di-reset, jalankan migration terbaru agar master izin `Tugas Luar`, master asal sekolah, jenis santri resmi terbaru, kolom `attendance_key` absensi, dan metadata asal sekolah terbaru masuk ke database existing:

```bash
php artisan migrate
```

Setelah update 13 Mei 2026, jalankan juga generator tagihan agar rule pembayaran aktif membuat tagihan aktual:

```bash
php artisan payments:generate-bills
```

Setelah migration absensi terbaru, cek dan repair data absensi lama yang mungkin duplicate:

```bash
php artisan attendance:repair-duplicates --dry-run
php artisan attendance:repair-duplicates --apply
php artisan migrate
```

Jika butuh data uji realtime, jalankan seeder dummy idempotent:

```bash
php artisan db:seed --class=RealtimeDummySeeder
```

Catatan penting:

- `migrate:fresh --seed` menghapus semua data lama.
- Setelah menjalankan `migrate:fresh --seed`, wilayah harus di-import ulang.
- Import wilayah butuh memory lebih besar karena data desa/kelurahan banyak.
- Migration terbaru menambahkan master izin `Tugas Luar`, tabel `school_origins`, kolom `siswa.school_origin_id`, opsi jenis santri resmi, `absensi.attendance_key`, unique index `attendance_key`, serta metadata opsional `school_origins.city_id/npsn/jenjang/alamat/status_sekolah` tanpa menghapus data lama.
- Migration 13 Mei 2026 menambahkan `school_origins.province_id/district_id/source/external_id`, field `previous_school_origin_id/previous_asal_sekolah` pada `siswa`, tabel tagihan otomatis, dan `pembayaran.payment_bill_id`.
- Migration 15 Mei 2026 menambahkan tabel hak akses menu dan audit: `app_menus`, `role_menu_permissions`, dan `audit_logs`.
- Migration 16 Mei 2026 menambahkan field profil santri, status mondok, tanggal diterima pondok/sekolah, field tahun ajaran aktif, dan relasi periode akademik nullable pada tabel operasional.
- Migration 16 Mei 2026 lanjutan menambahkan periode akademik pada `hafalan` agar nilai/hafalan bisa mengikuti filter tahun ajaran dan semester.
- Migration 17 Mei 2026 menambahkan tabel `siswa_tahun_ajaran` untuk sinkronisasi santri per tahun ajaran/semester, index pembayaran/tagihan, dan guard pembayaran bulanan agar SPP per bulan tidak dobel.
- Migration `school_origins` men-seed master asal sekolah dari data siswa existing dan menormalisasi awalan umum seperti `MI`, `SD`, `MTs`, `SMP`, `MA`, `SMA`, dan `SMK`.
- Migration 9 Mei 2026 untuk `school_origins` sudah divalidasi dengan `php artisan migrate --pretend`; jalankan `php artisan migrate` untuk menerapkannya ke database existing.
- Migration 13 Mei 2026 sudah divalidasi dengan `php artisan migrate --pretend --no-interaction`; jalankan `php artisan migrate` untuk menerapkannya ke database existing.
- `attendance_key` dipakai agar 1 siswa, 1 tanggal, 1 kelas, 1 mapel, dan 1 jadwal hanya punya 1 absensi.
- Untuk database lama, jalankan repair duplicate sebelum unique index aktif penuh.

## 7. Jalankan Backend

Untuk emulator Android, pakai host yang bisa diakses dari HP/emulator.

Mode lokal biasa:

```bash
php artisan serve --host=0.0.0.0 --port=8000
```

Jika `php artisan serve` sering gagal di laptop, boleh pakai server PHP bawaan:

```bash
php -S 0.0.0.0:8000 -t public
```

Backend akan aktif di:

```text
http://127.0.0.1:8000
http://IP-LAPTOP:8000
```

Untuk emulator Android Studio, biasanya host laptop bisa diakses dengan:

```text
http://10.0.2.2:8000
```

Untuk HP fisik, gunakan IP WiFi laptop, contoh:

```text
http://192.168.1.10:8000
```

## 8. Jalankan Backend Online Sementara dengan Cloudflare

Selama belum memakai VPS, laptop boleh dianggap sebagai server sementara.

Terminal 1:

```bash
cd C:\Users\Nobita\absensi_android\absensi_backend
php -S 0.0.0.0:8000 -t public
```

Terminal 2:

```bash
cloudflared tunnel --protocol http2 --edge-ip-version 4 --url http://127.0.0.1:8000
```

Jika jaringan mendukung QUIC dengan stabil, command pendek ini juga bisa dipakai:

```bash
cloudflared tunnel --url http://localhost:8000
```

Alur online sementara:

```text
APK di HP -> URL Cloudflare -> laptop -> Laravel -> PostgreSQL
```

Catatan:

- terminal backend dan terminal Cloudflare harus tetap hidup;
- jika URL Cloudflare berubah, APK lama tidak akan konek;
- jika URL berubah, ubah `ApiService.baseUrl`, ubah `APP_URL` di `.env`, lalu build APK ulang.
- error QUIC biasanya masalah jaringan/UDP/firewall, bukan berarti Laravel rusak.

## 14. Troubleshooting Cepat

Backend tidak konek database:

- cek PostgreSQL hidup;
- cek `.env`;
- cek nama database `absensi_db`;
- jalankan `php artisan config:clear`.

Foto profil 404:

- jalankan `php artisan storage:link`;
- cek file di `storage/app/public`;
- cek URL `/storage/...`;
- upload ulang jika file fisik memang hilang.

Wilayah kosong:

- jalankan ulang `php -d memory_limit=512M artisan regions:import-sql`;
- cek tabel `provinces`, `cities`, `districts`, `villages`.

Import siswa menampilkan warning:

- cek kolom opsional seperti `jenis_santri`, wilayah, pendidikan, pekerjaan, penghasilan, tempat tinggal, transportasi, dan golongan darah;
- cek juga `asal_sekolah`; nilai harus cocok master `school_origins` jika diisi;
- warning berarti field opsional tidak cocok master lalu dikosongkan;
- NIS, nama lengkap, jenis kelamin, NIS duplikat, tanggal invalid, dan email invalid tetap menjadi error.
- jenis santri input baru hanya `Santri Pondok`, `Santri Madin`, atau `Keduanya`.

Asal sekolah tidak muncul di Edit Data Santri:

- jalankan `php artisan migrate` agar tabel `school_origins` dan `siswa.school_origin_id` ada;
- cek endpoint `php artisan route:list --path=api/school-origins`;
- pastikan user login admin/guru dan backend yang aktif sudah kode terbaru.
- update 9 Mei 2026: endpoint mendukung `GET /api/school-origins?city_id=...&search=...&limit=...`; jika filter kota kosong, cek apakah data `school_origins.city_id` sudah terisi atau nama sekolah legacy masih mengandung nama kota.
- update 13 Mei 2026: endpoint juga mendukung `province_id` dan `district_id`; jika filter terlalu sempit, cek apakah master sekolah sudah punya `province_id/city_id/district_id` yang benar.
- Edit Data Santri sekarang punya dua field: `Sekolah Asal Sebelumnya` dan `Sekolah Asal Siswa Sekarang`.
- master sekolah nasional sebaiknya di-import/cache lokal dari sumber resmi NPSN/Kemendikbud, bukan mengambil internet langsung setiap picker dibuka.

Tagihan bulanan tidak muncul di wali/admin:

- jalankan `php artisan migrate` agar tabel `payment_bill_rules`, `payment_bills`, dan `payment_bill_notifications` tersedia;
- jalankan `php artisan payments:generate-bills`;
- cek route `php artisan route:list --path=payment`;
- pastikan tipe pembayaran berstatus `Aktif`;
- pastikan siswa target berstatus aktif dan punya `wali_id` jika ingin muncul di akun wali;
- generator aman dijalankan berulang karena mencegah duplikat per rule, siswa, dan periode.

Pekerjaan Ayah masih menampilkan `Ibu Rumah Tangga`:

- pastikan APK sudah dari kode update 9 Mei 2026;
- backend tetap memakai satu master `occupations`;
- filtering dilakukan di UI: pekerjaan ayah menyembunyikan `Ibu Rumah Tangga`, pekerjaan ibu/wali tetap menampilkan.

Menu Nilai tidak menampilkan pilihan kelas:

- jalankan `php artisan migrate` agar master `classes` tersedia dari baseline/migration;
- cek endpoint `php artisan route:list --path=api/classes`;
- pastikan data kelas aktif ada di tabel `classes`;
- untuk admin, mapel yang muncul adalah semua mata pelajaran `Aktif`;
- untuk guru, mapel yang muncul tetap mengikuti mata pelajaran dan jadwal aktif yang ditugaskan admin.

Menu Biodata Siswa wali tidak muncul atau kosong:

- pastikan APK sudah dari kode terbaru karena menu ini ada di dashboard role wali;
- cek route `php artisan route:list --path=api/wali/biodata --except-vendor`;
- pastikan siswa terhubung ke akun wali lewat `wali_id` atau `guardian_profile_id`;
- wali hanya bisa melihat biodata anak sendiri dan tidak punya akses edit.
- jika `Wali Sama Dengan` adalah `Ayah` atau `Ibu`, pekerjaan wali harus ikut pekerjaan ayah/ibu; jika masih `-`, pastikan APK dan backend sudah dari update 7 Mei 2026.

Menu Izin Guru tidak muncul:

- ini kondisi sengaja sejak update 8 Mei 2026;
- fitur Izin Guru dinonaktifkan karena bug dan akan dibuat ulang nanti;
- menu admin/guru, screen Flutter, service export, method API Flutter, route `guru-izin`, controller, dan model sudah dibersihkan;
- database/schema/migration `guru_izin` dan `leave_types` tetap dipertahankan agar data lama aman.

Route `guru-izin` masih muncul:

- pastikan backend yang berjalan sudah kode terbaru;
- jalankan `php artisan route:list --path=api --except-vendor`;
- pada update 8 Mei 2026, route `guru-izin` seharusnya tidak tampil.

Edit Data Santri pilihan wali kembali ke `Ibu`:

- pastikan kode terbaru sudah terpasang;
- pilihan resmi yang dikirim adalah `Ayah`, `Ibu`, atau `Wali`;
- tombol UI `Lainnya` disimpan sebagai `Wali`;
- buka ulang detail setelah simpan untuk memastikan label detail mengikuti data terbaru.
- update 7 Mei 2026 juga mensinkronkan pekerjaan wali, `guardian_occupation_id`, alamat wali, dan nomor telepon wali dari ayah/ibu.

Tempat Lahir siswa/orang tua masih bisa typo:

- pastikan layar Edit Data Santri sudah memakai picker Kota/Kabupaten;
- picker memakai master `cities` lewat `GET /api/regions/cities`;
- jika daftar kota kosong, jalankan `php -d memory_limit=512M artisan regions:import-sql`;
- nilai tempat lahir masih disimpan sebagai label kota/kabupaten resmi, belum ada kolom `birth_city_id`.
- update 8 Mei 2026: saat picker dibuka ulang, daftar kota/kabupaten harus tampil penuh, bukan hanya kota terakhir yang pernah dipilih seperti Kabupaten Gresik.
- update 8 Mei 2026 lanjutan: picker Tempat Lahir siswa/ayah/ibu memakai bottom sheet mandiri agar tidak muncul layar merah `'_dependents.isEmpty'` saat memilih kota.
- data lama seperti `Gresik` akan dicoba dinormalisasi menjadi `Kabupaten Gresik` jika cocok dengan master `cities`.
- jika teks terlihat terpotong seperti `abupaten Gresik`, pastikan APK sudah dari kode terbaru karena controller text harus di-reset ke posisi awal setelah kota dipilih.

Jadwal mapel gagal dengan pesan `day_id`:

- pastikan backend sudah kode update 8 Mei 2026;
- `JadwalController` sekarang otomatis resolve `hari` ke `day_id` sebelum validasi jadwal aktif;
- jika masih gagal, cek tabel `days` berisi `Ahad`, `Senin`, `Selasa`, `Rabu`, `Kamis`, `Jumat`, dan `Sabtu`;
- tambah Guru Pengajar dulu sampai muncul pesan sukses, baru tambah Jadwal Pelajaran.

Jadwal mapel gagal karena bentrok kelas:

- update 9 Mei 2026: yang tetap ditolak adalah bentrok guru yang sama pada hari/jam overlap;
- jadwal paralel untuk guru/mapel berbeda boleh disimpan walaupun kelas/hari/jam sama sesuai arahan terbaru;
- jika masih muncul pesan bentrok kelas, pastikan backend yang berjalan sudah kode terbaru dan jalankan `php artisan optimize:clear`.

Pembayaran gagal simpan dengan log `POST /api/pembayaran [500]`:

- buka `absensi_backend/storage/logs/laravel.log`;
- jika muncul `pembayaran_jenis_check`, artinya tipe pembayaran custom masuk ke kolom legacy `pembayaran.jenis`;
- backend terbaru sudah memetakan tipe custom agar kolom legacy aman, misalnya `Kitab` menjadi `Buku & Kitab`;
- restart backend setelah update kode agar fix aktif;
- pastikan tipe pembayaran yang dipilih aktif dan metode bayar didukung oleh tipe tersebut.

Rekap PDF pembayaran wali gagal:

- jalankan `php artisan optimize:clear` setelah update route;
- cek `php artisan route:list --path=api/pembayaran/rekap-siswa --except-vendor`;
- route harus muncul satu kali dan bisa dipakai role `admin,wali`;
- role wali tetap hanya bisa rekap pembayaran anak yang terhubung ke akun wali aktif;
- jika dialog cetak/download HP gagal, aplikasi akan mencoba fallback simpan file sementara dan share PDF.
- jika siswa belum punya transaksi pembayaran, tombol download rekap memang disembunyikan.

Edit Data Santri gagal karena email/telepon kosong:

- pastikan APK sudah dibuild dari kode terbaru;
- field opsional kosong harus tetap kosong/null, bukan `-`;
- field wajib tetap `NIS`, `Nama Lengkap`, dan `Jenis Kelamin`;
- jika error masih muncul, cek pesan validasi apakah ada value `-` yang terkirim ke `email_siswa`.

Upload foto santri atau dokumen akta:

- pastikan backend aktif dan storage link sudah dibuat;
- jalankan `php artisan storage:link` jika file tidak bisa dilihat dari aplikasi;
- file siswa diupload ke `/api/upload`, lalu database menyimpan path server;
- foto santri memakai image, dokumen akta boleh image/PDF;
- batas file backend 5 MB.

Upload materi/kegiatan gagal saat offline:

- pastikan internet dan server backend aktif;
- upload tidak dijalankan jika data referensi hanya dari cache/offline;
- materi wajib memilih kelas dan mapel resmi;
- kegiatan wajib memilih kelas resmi.

Absensi offline gagal sync:

- cek pesan gagal di data pending karena sekarang sistem menyimpan detail error backend jika tersedia;
- pastikan `class_id`, `mapel_id`, `jadwal_id`, dan `attendance_status_id` masih valid.
- jika pesan conflict muncul, artinya data server sudah masuk lebih dulu dan pending offline tidak menimpa data server.
- pending offline hanya bisa diedit oleh akun/actor yang membuat pending tersebut.

Absensi muncul double atau dashboard menampilkan `Unknown`:

- pastikan backend sudah migration terbaru yang menambahkan `absensi.attendance_key`;
- simpan absensi baru dan edit absensi lama harus memakai scope lengkap `tanggal`, `class_id`, `mapel_id`, `jadwal_id`, dan `siswa_id`;
- jalankan `php artisan attendance:repair-duplicates --dry-run` untuk audit data lama;
- jika hasil dry run aman di database uji, lanjutkan `php artisan attendance:repair-duplicates --apply`;
- jalankan `php artisan migrate` setelah repair agar unique `attendance_key` aktif;
- dashboard terbaru tidak menampilkan absensi yang scope jadwalnya tidak lengkap, jadi data `Unknown` berarti backend/APK yang berjalan belum kode terbaru atau ada cache lama.

Absensi sudah completed online lalu HP offline:

- data completed dari server dikunci di mode offline;
- tidak boleh absen ulang, edit, atau batal sampai koneksi online kembali;
- admin tetap full access saat online, tetapi pending offline admin tetap kalah jika data server sudah ada lebih dulu.

Jumlah santri/mapel di daftar Absensi tidak sama dengan detail:

- pastikan backend memakai update 8 Mei 2026 lanjutan pada `KelompokBelajarController`;
- daftar Absensi Sifir harus memakai `class_id` asli, bukan id kelompok belajar;
- `jumlah_siswa` dihitung dari siswa aktif berdasarkan `class_id`, sama seperti layar detail absensi;
- `jumlah_mapel_aktif` dihitung dari jadwal aktif dan mapel aktif untuk kelas tersebut;
- jika angka masih 0 tetapi detail ada siswa, restart backend dan tarik refresh menu Absensi.

Mata pelajaran/jadwal guru tidak muncul:

- pastikan jadwal aktif memiliki `class_id`, `mapel_id`, `teacher_id`, hari, jam mulai, dan jam selesai;
- guru hanya melihat jadwal/mapel yang menjadi assignment dirinya;
- jadwal aktif sekarang menolak bentrok guru yang sama pada hari/jam yang overlap; jadwal paralel guru/mapel berbeda boleh disimpan.
- saat tambah/edit jadwal dari Edit Mata Pelajaran, guru pengajar harus sudah tersimpan di relasi `mapel_guru` sebelum `sync-group` dipanggil.
- jika muncul "Semua guru sudah ditambahkan" padahal kosong, pastikan endpoint `GET /api/guru` mengembalikan guru aktif dengan ID valid dan APK sudah kode terbaru.
- update 9 Mei 2026: Edit Mata Pelajaran memakai cache guru aktif dan retry loading; jika data guru belum termuat, tunggu loading/retry, jangan langsung menekan tambah jadwal.

Mata pelajaran di menu Absensi admin tidak muncul:

## 17. Catatan Penting

- Jangan reset database kalau sudah ada data sungguhan tanpa backup.
- Jangan ubah UI hanya untuk menyesuaikan database.
- Jangan input master data langsung dari typo user.

- Setelah migration, admin bisa membuka Pengaturan > Hak Akses Menu untuk mengatur menu Guru/Wali.

- Setelah update 16 Mei 2026, admin bisa membuka Buku Induk > Setting Akademik untuk mengatur tahun ajaran dan semester aktif.
